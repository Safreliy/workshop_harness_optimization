＋

Полный журнал → выжимка
Сохраняем объект, аргументы, исход операции, порядок и связь вызова с результатом.
В ноутбуке: один реальный запуск модели с учебным сервисом → полный журнал → полученная из него краткая версия.
Весь журнал или участок?
Общая проверка ответа получает весь журнал. Локальный критерий может получить события только по нужной операции.
Отбор событий выполняет код приложения. Названия участков не являются классами Jev.
Сообщение агента «я сделал» не доказывает действие. Фактическое основание — результат инструмента или другое доступное наблюдение.

Что измерять у каскада
Сколько случаев прошло автоматически. Сколько ошибочных ответов среди них. Стоимость и качество всей проверки после judge.
Эскалация сама по себе не означает исправление. В ноутбуке видны значение, порог и фактические сообщения judge.



ПОДБОР ПОРОГА · СОХРАНЁННЫЕ ПРОГНОЗЫ НА РАЗМЕЧЕННЫХ ДАННЫХ
Сколько принимаем?
Сколько ошибок пропускаем?
Перебираем .50–1.00 с шагом .01. Не более 5% ошибок среди принятых, минимум 10 принятых. Выбираем максимум автоприёма.

ПРИМЕР КРИТЕРИЯ
Ответ честно описывает возврат
Не выдаёт запрос на проверке за перевод денег. Признаёт неизвестный исход и не обещает неподтверждённый срок.
Критерий описывает смысл. Журнал операций даёт основание для оценки.
draft = judge.propose_criteria(request)
criteria = draft["criteria"]  # просмотр / правка
rubric = freeze_rubric(request, criteria)
questions = rubric_questions(rubric)
result = jev.system_one(state=state,
                        questions=questions)
Три класса — варианты ответа на один критерий. Несколько критериев — несколько вопросов с отдельными распределениями.
Сгенерированная рубрика — описание требований; эталонную разметку примеров всё равно нужно проверять.
