## 1.1. Установка

Для основного SQL/report-эксперимента нужны Python 3.11+, Docker с командой `docker compose` и модель с tool calling. Compose должен поддерживать `up --wait`; конкретные минимальные версии Docker/Compose в проекте не закреплены. ETL-домашка работает на SQLite и Docker не требует.

Выполните из корня репозитория:

```bash
python -m pip install -e ".[notebooks]" jupyterlab
```

Поднимите benchmark-базу в Docker:

```bash
harness-lab db-up
```



## 1.2. Конфигурация .env

Скопируйте `.env.example` в `.env`

Укажите параметры подключения к модели:

`BASE_URL` — URL OpenAI-совместимого провайдера. Например:
	[https://openrouter.ai/api/v1](https://openrouter.ai/api/v1)
	[https://api.aitunnel.ru/v1](https://api.aitunnel.ru/v1)

`MODEL_NAME` — идентификатор модели с tool calling у выбранного провайдера. Для OpenRouter нужен полный идентификатор из его каталога.

`API_KEY` - токен для аутентификации

`.env` остаётся локальным и исключён из Git. Если используется приватный CA или proxy, параметры описаны в [образце окружения](../../.env.example). Не выводите ключ при показе экрана.

## 1.3. Проверка окружения

Проверьте настройки и доступность сервисов:

```bash
harness-lab doctor
```

## 1.4. Запуск

Запустите локальный сервер для презентации и живой арены:

```bash
python -m harness_lab.workshop_server --port 8867
```

Откройте `http://127.0.0.1:8867/workshop-v2/` и пройдите обучение

# Эксперименты

## case #1. Улучшить Harness для решения задач по SQL/report

[**Теоретическая часть**](../../workshop-v2/index.html) — HTML-презентация об оптимизации SQL и составлении спецификаций отчётов. Рассматриваются ошибки агента, оценка качества ответов, ручки harness и мета-поиск.

[**Практическая часть**](../../notebooks/01_agent_and_harness.ipynb) — Jupyter Notebook для получения навыков работы с агентным циклом, вызовом тулов, конфигурированию HarnessConfig и наблюдение за работой мета-оптимизатора.

Вводный ноутбук использует SQLite и программную policy: его учебный проход не требует API и PostgreSQL. Сохранённые слайды и траектории также доступны без API. Новые прогоны SQL/report требуют модели и PostgreSQL.

Уже есть [начальные настройки harness](../../configs/baseline.yaml) и проведён поиск кандидатов HarnessConfig, их сравнение и выбор [кандидата по результатам эксперимента](../../configs/optimized.yaml).
Доступна также [Арена](../../workshop-v2/demo.html) — сравнение сохранённых eval-запусков и полные траектории (логи выполнения задачи агентом); через сервер можно запускать новые задачи.



Можно самому получить новые результаты прогонов по case #1 с настоящей БД и LLM:
**Запуск дефолтного HarnessConfig на 10 train-задачах**

```bash
harness-lab benchmark --config configs/baseline.yaml --split train
```

**Запуск**  **мета-поиска кандидатов HarnessConfig'ов  на train задачах**

```bash
harness-lab train --search-config configs/search.yaml --output artifacts/training/my-search
```

**Запуск   дефолтного HarnessConfig и candidate HarnessConfig на одинаковых eval-задачах и показывает разницу score.**

```bash
harness-lab eval --candidate artifacts/training/my-search/best_config.yaml
```



Измеренная конфигурация занятия сохранена в `configs/optimized.yaml`.

## case #2. Домашнее задание. Улучшить Harness для решения задач по ETL

подробнее в [README.md](../../homework/README.md)

[**Постановка задания**](../../homework/index.html) — задача, инструменты и критерии оценки ETL-агента.

[**Практическая часть**](../../homework/etl_homework.ipynb) — ноутбук для ручного улучшения `ETLHarnessConfig`: инструкции, инструменты, бюджет и цикл ETL-агента. Первый проход без API воспроизводит сохранённые SQL на SQLite; новые ответы агента требуют подключения модели. Весь путь `smoke → train → dev → select → test` выполняется из ноутбука, отдельный терминал и установка основного SQL/report-проекта не нужны.

В этом ДЗ `ACTION="train"` запускает контроль и одного кандидата на 24 train-задачах. Гипотезы и правки предлагает участник; автоматический мета-поиск этим действием не вызывается. Это отличается от CLI `harness-lab train` выше, который сам предлагает и оценивает конфигурации SQL/report.

| Этап в ноутбуке | Назначение |
|---|---|
| `smoke` | 3 train-задачи для каждого варианта: проверка запуска |
| `train` | 24 задачи для каждого варианта: разбор ошибок и правки |
| `dev` | 12 других задач для каждого варианта: выбор настроек |
| `select` | Сохранение выбора и копий конфигов; без вызовов модели |
| `test` | 12 отложенных задач: контроль и выбранный вариант |

`ACTION` выбирает действие. `SELECT="auto" / "control" / "candidate"` задаёт способ выбора только на этапе `select`; `auto` сравнивает результаты dev. Результаты лежат в `homework/results/<EXPERIMENT>/`. Изменили конфиг, код или модель — начните новый `EXPERIMENT`. Test используют после окончательного выбора.

[ДЗ одним HTML](../../homework/homework.html) можно отправить отдельно: внутри встроен полный архив с ноутбуком, средой, данными и проверками
