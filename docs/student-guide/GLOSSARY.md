# Глоссарий

Конспект участника, проверен по коду. Общие определения и конкретные параметры учебной реализации перечислены отдельно. [К запуску и экспериментам](README.md).

## AI и агентные системы

- **LLM (Large Language Model)** — большая языковая модель, генерирующая ответ по входному контексту.
- **System One model** — термин TypeSafe для модели, возвращающей типизированные решения и вероятности вместо свободного текста.
- **Jev** — модель System One от TypeSafe для классификации, оценки по шкале и оценки вероятности утверждений.
- **Choice** — выбор из заранее заданных вариантов ответа.
- **Score** — численная оценка по заданной шкале.
- **Noul** — тип вопроса в TypeSafe API, возвращающий оценку вероятности истинности утверждения.
- **Калибровка вероятностей** — соответствие предсказанных вероятностей частотам правильных исходов на множестве примеров.
- **AI agent** — система, выбирающая и выполняющая действия для достижения цели.
- **Harness** — программная обвязка, управляющая контекстом, инструментами и выполнением модели.
- **Prompt** — входные инструкции, задача и примеры для модели.
- **Контекст** — информация, доступная модели при генерации ответа.
- **Token** — единица представления текста: слово, часть слова или знак.
- **Temperature** — параметр, регулирующий случайность выбора токенов при генерации.
- **Confidence** — показатель, определение которого зависит от API. В Jev это отдельная характеристика распределения ответов; она не равна вероятности правильности выбранного класса. Для порога берём вероятность нужного класса и проверяем её на размеченных данных.
- **Tool call** — структурированный запрос модели на выполнение инструмента.
- **Observation / наблюдение** — результат действия или данные, полученные агентом от среды.
- **Tool description** — описание назначения, аргументов и ограничений инструмента.
- **ReAct (Reasoning + Acting)** — подход, чередующий рассуждения, действия и наблюдения.
- **Plan → Execute** — подход, разделяющий составление плана и его выполнение.
- **Workflow** — порядок и правила выполнения действий.
- **Routing** — направление задачи к подходящей модели, процессу или инструментам.
- **Review** — проверка результата и предложение исправлений.
- **Reviewer** — компонент или участник, проверяющий результат.
- **Субагент** — агент, которому поручена отдельная подзадача.
- **Forced finalization** — принудительный переход к финальному ответу по условию остановки.
- **LLM call** — одно обращение к языковой модели.

## Управление контекстом

- **Context partition** — разделение информации между этапами или участниками процесса.
- **Shared context** — контекст, доступный нескольким участникам или этапам.
- **Stage-isolated context** — отдельный контекст для конкретного этапа.
- **Raw history** — исходная история сообщений без смыслового сжатия.
- **Summary** — краткое изложение основных сведений.
- **Requirements ledger** — структурированный реестр требований, их статусов и источников. В SQL/report-агенте это результат отдельного LLM-вызова перед решением report-задачи: активные и отменённые требования, недоступные данные, вопросы и ссылки на реплики. Затем он используется вместо полного диалога вместе с последними четырьмя репликами; автоматически после каждого шага не пополняется. Summary — свободное резюме; отличие ledger — явно заданная структура и сохранение происхождения требований, а не особый тип памяти.
- **Provenance** — сведения о происхождении данных или утверждения.
- **Dynamic compaction** — сокращение контекста во время выполнения задачи.
- **State checkpoint** — сохранённое состояние, позволяющее продолжить работу.

## Данные и требования

- **ETL (Extract, Transform, Load)** — извлечение, преобразование и загрузка данных.
- **ETL-агент** — агент, выполняющий задачи извлечения, преобразования и загрузки данных.
- **ТЗ** — документ с требованиями к результату и условиям выполнения работы.
- **Report contract** — спецификация состава, правил расчёта и формата отчёта.
- **Grain** — уровень детализации данных: что представляет одна строка.
- **Late correction** — изменение требования, внесённое позднее первоначальной формулировки.
- **Unavailable data** — данные, недоступные для решения задачи.
- **Artifact** — сохраняемый результат работы: документ, код, таблица или файл.
- **Pipeline** — последовательность связанных операций обработки.
- **Revision** — версия записи, документа или события.
- **Latest revision** — последняя версия по принятому правилу упорядочения.
- **Repeated delivery** — повторная доставка тех же данных или события.
- **Event identifier** — идентификатор отдельного события.
- **Deduplication** — устранение повторных записей одного объекта или события.
- **Settled** — статус завершённого расчёта по финансовой операции.
- **Pending** — статус операции, ожидающей завершения.
- **Failed** — статус операции, завершившейся ошибкой.
- **Currency matching** — проверка совпадения валют связанных сумм или операций.
- **Money cents** — денежная сумма в целых сотых долях единицы валюты.
- **Leading zeros** — нули в начале строкового представления значения.
- **Independent aggregation** — раздельное вычисление агрегатов до объединения результатов.
- **Idempotence / идемпотентность** — свойство операции: повторное применение не меняет результат первого применения.

## PostgreSQL и SQL

- **PostgreSQL** — объектно-реляционная система управления базами данных.
- **Schema** — пространство имён объектов внутри базы PostgreSQL.
- **Планировщик запросов** — компонент СУБД, выбирающий способ выполнения запроса по оценкам стоимости.
- **EXPLAIN** — SQL-команда, показывающая план запроса и оценки планировщика.
- **EXPLAIN ANALYZE** — выполнение запроса с выводом плана и фактической статистики выполнения.
- **Query plan** — дерево операций, выбранных для выполнения запроса.
- **Total Cost** — оценка стоимости полного выполнения узла с дочерними узлами в условных единицах планировщика.
- **Baseline query** — исходный запрос для сравнения.
- **Candidate query** — проверяемый вариант запроса.
- **Index** — дополнительная структура доступа, ускоряющая подходящие операции с данными.
- **Index trial** — экспериментальная проверка влияния индекса на запрос.
- **Sargability** — пригодность условия запроса для индексного доступа.
- **Read-only** — режим транзакции, ограничивающий изменения данных и объектов.
- **SQL safety** — ограничения, обеспечивающие допустимое и контролируемое выполнение SQL.
- **Semantic equivalence** — одинаковый результат запросов на всех допустимых входных данных.
- **Evidence** — данные и результаты проверок, подтверждающие вывод.

## Оценка и эксперименты

- **Claim** — утверждение, проверяемое по доступным данным.
- **NLI (Natural Language Inference)** — определение отношения между исходным текстом и проверяемым утверждением.
- **Entailment** — отношение, при котором утверждение следует из исходного текста.
- **Contradiction** — противоречие утверждения исходному тексту.
- **Insufficient evidence** — недостаток данных для подтверждения или опровержения утверждения.
- **LLM-as-a-Judge** — использование языковой модели для оценки по заданным критериям.
- **Decision threshold** — порог оценки, определяющий действие системы.
- **Auto-acceptance** — автоматическое принятие результата без дополнительной проверки.
- **Escalation** — передача случая более сложной модели или человеку.
- **Cascade** — последовательность проверок с переходом к следующей при необходимости.
- **Calibration set** — набор данных для настройки вероятностей или порогов.
- **Temperature scaling** — калибровка вероятностей делением логитов на подобранный положительный коэффициент.
- **Confusion matrix** — таблица соответствия истинных и предсказанных классов.
- **Accuracy** — доля правильных предсказаний.
- **Precision** — доля правильных предсказаний среди отнесённых к выбранному классу.
- **Recall** — доля обнаруженных примеров среди всех примеров выбранного класса.
- **Brier score** — средняя квадратичная ошибка предсказанных вероятностей относительно истинных исходов.
- **NLL (Negative Log-Likelihood)** — средний отрицательный логарифм вероятности правильного ответа.
- **ECE (Expected Calibration Error)** — оценка расхождения средней уверенности и точности по группам предсказаний.
- **Challenge set** — набор сложных примеров для проверки ограничений системы.
- **Grader** — компонент, оценивающий результат или процесс по заданным критериям.
- **Output score** — оценка качества конечного результата.
- **Trace / trajectory** — журнал событий и действий при выполнении задачи.
- **Trajectory score / trace score** — оценка процесса выполнения по заданным критериям.
- **Observable trace** — журнал фактически наблюдаемых событий выполнения.
- **Combined score** — итоговая метрика, объединяющая несколько оценок.
- **Pass rate** — доля запусков, прошедших критерии успеха.
- **Success episode** — отдельный запуск, прошедший критерии успеха.
- **Invariant** — условие, сохраняющееся при допустимых операциях или преобразованиях.
- **Counterexample / контрпример** — пример, опровергающий утверждение или выявляющий ошибку.
- **Regression** — ухудшение ранее корректного поведения после изменения.
- **Regression test** — проверка сохранения ранее корректного поведения.
- **Tool error** — ошибка запроса к инструменту или его выполнения.
- **Unnecessary tool use** — использование инструмента без пользы для решения задачи.
- **Latency** — время ожидания ответа или завершения операции.
- **Cost** — затраты денег или ресурсов на выполнение.
- **Benchmark** — набор задач и правил для воспроизводимого сравнения систем.
- **Case** — отдельная задача с входными данными и критериями оценки.
- **Train** — набор данных для обучения или настройки системы.
- **Dev / validation** — набор данных для выбора настроек и вариантов системы.
- **Eval** — оценивание системы; также название набора для оценки.
- **Test** — отложенный набор для итоговой оценки выбранной системы.
- **Holdout** — данные, исключённые из обучения или настройки для отдельной оценки.
- **Smoke test** — короткая проверка базовой работоспособности.
- **Candidate** — вариант системы, рассматриваемый для выбора.
- **Experiment** — проверка гипотезы в заданных условиях.
- **Repeat** — повтор запуска для оценки изменчивости результатов.
- **Hypothesis** — утверждение, которое можно проверить экспериментом.
- **Negative result** — результат, не подтвердивший проверяемую гипотезу.
- **Public validation** — проверки, доступные участнику или проверяемой системе.
- **Private reference** — эталон, скрытый от проверяемой системы.

## Модели и обучение

- **Encoder** — компонент модели, преобразующий вход в числовые представления.
- **Classification head** — слой, преобразующий представления в оценки классов.
- **Frozen encoder** — encoder с неизменяемыми при обучении весами.
- **Fine-tuning** — дополнительное обучение модели на целевых данных.
- **LoRA (Low-Rank Adaptation)** — адаптация модели обучением низкоранговых добавок к замороженным весам.
- **Logits** — выходные оценки модели до преобразования в вероятности.
- **Softmax** — функция преобразования оценок в распределение вероятностей.
- **Logprob** — логарифм вероятности токена или ответа.
- **Checkpoint** — сохранённые веса и настройки модели, иногда также состояние обучения.
- **Truncation** — усечение входа до допустимой длины.

## Поиск конфигураций

- **Meta-harness** — система поиска и оценки вариантов программной обвязки модели.
- **Meta-optimizer** — алгоритм, подбирающий настройки другой системы.
- **Meta-agent** — агент, управляющий работой или настройкой других агентов.
- **Proposal** — предложение изменения.
- **Patch** — набор изменений относительно исходной версии.
- **Parent** — исходный вариант, от которого получен новый.
- **Round** — один раунд поиска или сравнения вариантов.
- **Beam** — ограниченный набор перспективных вариантов, сохраняемых в поиске.
- **Beam width** — максимальное число одновременно сохраняемых вариантов.
- **Portfolio** — набор вариантов, рассматриваемых совместно.
- **Lineage** — история происхождения и изменений вариантов.
- **Pareto frontier** — варианты, не имеющие конкурента не хуже по всем критериям и лучше хотя бы по одному.
- **Objective** — целевая функция, определяющая предпочтительность варианта.
- **Call penalty** — штраф в целевой функции за обращения к модели.
- **Selection** — выбор варианта по заданным критериям.
- **Observed failure** — неуспех, подтверждённый наблюдением или проверкой.
- **Optimizer blind spot** — важное свойство, не учитываемое критериями оптимизации.
- **Config fingerprint** — вычисленный идентификатор содержимого конфигурации.

## Специфические термины и параметры воркшопа

Параметры ниже описывают SQL/report-агента из `src/harness_lab/agent.py`. ETL-домашка использует отдельные `run_agent` и `ETLHarnessConfig` из `homework/runtime/harness_lab/etl_agent.py`; одинаковые слова не означают идентичную реализацию.

### Конфигурация агента

- **`HarnessConfig`** — конфигурация инструкций, инструментов, контекста, процесса и лимитов агента.
- **`max_steps`** — лимит основных ходов модели; дополнительные этапы могут увеличить число LLM-вызовов.
- **`enabled_tools`** — список включённых инструментов до фильтрации routing.
- **`tool_description_profile`** — профиль описаний тех же инструментов: `terse` — краткое назначение; `diagnostic` — дополнительные указания, когда и зачем вызывать инструмент, как трактовать его результат и ограничения. Меняется описание для модели, а не код инструмента.
- **`ToolExecutor`** — исполнитель, разбирающий аргументы и вызывающий инструменты.
- **`workflow=plan_execute`** — отдельный вызов модели для плана перед ReAct-циклом.
- **`routing=task_kind`** — фильтрация по `case.kind` из benchmark: report получает пустой список инструментов, SQL — настроенный набор. Это маршрутизация по готовой метке, отдельного LLM-классификатора здесь нет.
- **`routing=none`** — отсутствие фильтрации инструментов по типу задачи.
- **`review_mode=domain_specialist`** — дополнительный вызов той же модели с отдельными сообщениями роли reviewer, без инструментов; исправленный полный ответ заменяет исходный. Это этап пайплайна, а не независимый второй агентный цикл.
- **`context_partition=shared`** — передача reviewer полного исходного задания и финального ответа; история tool-вызовов не передаётся.
- **`context_partition=stage_isolated`** — передача reviewer подготовленного `task_text` и финального ответа.
- **`max_context_chars`** — лимит начального `task_text` в символах, включая постановку и контракт ответа. Это обрезка до начала цикла, а не порог динамической компакции растущей истории и не число токенов.
- **`_clip`** — сохранение начала и конца текста с заменой середины маркером.
- **`context_strategy=raw`** — исходный диалог без смыслового сжатия.
- **`context_strategy=requirements_ledger`** — создание реестра требований перед report-циклом.
- **`forced_final`** — дополнительный вызов модели без инструментов после исчерпания шагов: модель заново просят вернуть финальный JSON. Код не извлекает его поиском из прежнего текста. Само событие не означает ошибку, но не гарантирует правильный результат.
- **Forced final error** — неформальное название неуспеха после исчерпания бюджета.

### Задачи и инструменты

- **SQL-задача** — снижение стоимости плана с сохранением результата запроса.
- **Report-задача** — составление JSON-контракта отчёта из диалога с изменениями требований.
- **`list_tables`** — список таблиц `public` с оценками числа строк и размеров.
- **`describe_table`** — столбцы, типы, допустимость NULL, индексы и оценочное число строк таблицы.
- **`inspect_indexes`** — имена и определения индексов таблицы.
- **`run_readonly_query`** — выполнение разрешённого запроса в READ ONLY с ограничением выдачи.
- **`database_context`** — сведения о таблицах, размерах и условиях диагностики.
- **`explain_query`** — получение плана через `EXPLAIN (FORMAT JSON)` без выполнения запроса.
- **`trial_index_plan`** — сравнение планов с реальными пробными индексами и откатом транзакции.
- **`cost_ratio`** — `baseline_total_cost / candidate_total_cost`; больше 1 означает снижение стоимости плана.

### ETL и оценка

- **ETL-правило ревизий** — выбор максимальной целочисленной ревизии до фильтрации статуса события.
- **ETL-правило валюты** — учёт события только при совпадении его валюты с валютой заказа.
- **`paid_cents`** — сумма подходящих settled-платежей в целых центах или копейках.
- **`refunded_cents`** — сумма подходящих settled-возвратов в целых центах или копейках.
- **`net_cents`** — `paid_cents - refunded_cents`, без ограничения снизу нулём.
- **SQL/report combined score** — `0.75 × output_score + 0.25 × trajectory_score`.
- **SQL/report pass** — `output_score ≥ 0.8` и `trajectory_score ≥ 0.7`.
- **Полный ETL-успех** — совпадение таблицы с эталоном, устойчивость к повтору и перестановке входов.
- **Train-поиск** — подбор конфигурации harness без изменения весов модели. CLI `harness-lab train` запускает автоматический SQL/report-поиск; ETL `ACTION="train"` только измеряет контроль и кандидата, а правки предлагает участник.
- **Открытый eval** — повторно используемый набор SQL/report для сравнения конфигураций.
- **ETL-протокол** — `smoke → train → dev → select → test`; 3 smoke-задачи на вариант, затем 24 train / 12 dev / 12 test. `select` сохраняет выбор, новых задач не исполняет. Одна серия сравнивает контроль и одного кандидата.
- **Objective поиска** — `score - call_penalty × max(avg_llm_calls - 1, 0)`; стандартный коэффициент — `0.006`.
- **`CONNECT`** — включение подключения к модели в ETL-ноутбуке.
- **`RUN_LIVE`** — разрешение новых вызовов модели в ноутбуке.
